# Lot 4 — Chargement mobile dynamique et hors connexion des contenus

Réalisé par Claude (quota ChatGPT épuisé jusqu'à 10 h 05), le 13 novembre 2026. Aucun commit poussé, aucun déploiement, aucune base distante utilisée.

## Comportement livré

- **Contenus publiés sans nouvelle version de l'app.** À l'ouverture, au retour au premier plan (au plus une fois par minute) et au choix d'un programme, l'app lit `GET /api/prep/manifest`, télécharge les programmes nouveaux ou modifiés et les modules des programmes suivis, chacun dans sa **révision exacte** (`?revision=N`), puis redessine les écrans de préparation.
- **Pack embarqué conservé comme base.** `npm run prep:pack` ajoute au pack `empreintes.modules` (SHA-256 calculée comme le registre de publication du lot 3). Un module publié avec la même empreinte n'est **jamais retéléchargé** : l'app garde la version embarquée et ses clés, donc la correction instantanée hors connexion. Le test de contrat vérifie l'égalité des empreintes après un vrai aller-retour MongoDB.
- **Correction serveur des exercices téléchargés.** Le serveur retire les clés des exercices notés : l'app ne calcule donc **aucune note** pour eux. La réponse part dans la file existante (`POST /api/prep/sync`, clé d'action idempotente) et la correction revient avec le résultat. Hors connexion, l'écran affiche « Réponse enregistrée », l'exercice est figé et la réponse est corrigée à la synchronisation suivante. Le bilan indique « Score provisoire » (« Note provisoire » au concours blanc) et le nombre de réponses en attente. Les mini-questions non notées des leçons restent corrigées sur l'appareil.
- **Pas de mélange de révisions dans une session.** Si une nouvelle révision arrive pour un module utilisé par une session non terminée, elle attend (`differes`) et n'est appliquée qu'à la fin de la session. Un module retiré reste lisible jusqu'à la fin d'une session qui l'utilise.
- **Retraits.** Un programme ou un module absent du manifeste disparaît, y compris du pack embarqué. La progression déjà acquise n'est pas touchée.
- **Robustesse.**
  - Un manifeste illisible ou d'un schéma inconnu est ignoré, et le cache précédent reste utilisé.
  - Une génération plus ancienne que le cache est ignorée (réponses croisées).
  - Un serveur encore en mode pack (génération 0) laisse le pack embarqué faire foi.
  - Un téléchargement échoué (réseau, 401 ou 403 sans droits) garde l'ancienne révision.
  - Le cache est un fichier séparé de la progression (`fatafalta-prepa-contenus.v1.json`), écrit dans un fichier temporaire puis renommé. Un cache tronqué est assaini entrée par entrée.
- **Catalogue de l'onboarding.**
  - Toutes les pages de `/api/prep/catalogue` sont lues.
  - Les organismes et cycles publiés après la sortie de l'app apparaissent ; les cycles retirés sont masqués.
  - Hors connexion, le catalogue local reste affiché.

**Couverture des tests**

- Test de contrat, sur une base réelle :
  - import du pack, puis aucune requête de module ;
  - publication admin d'un nouveau programme et d'un nouveau module, qui apparaissent dans le catalogue et sur le mobile ;
  - le module partagé reste embarqué ;
  - aucune clé ni explication dans le module téléchargé ;
  - correction serveur via la file, puis rejeu compté une seule fois ;
  - 401 sans identité, et cache inchangé ;
  - nouvelle révision servie, report pendant une session ;
  - retrait groupé.
- Tests mobiles :
  - empreintes, manifeste identique, nouvelle traduction, mise à jour d'exercice ;
  - manifestes incompatibles ou illisibles, générations dans le désordre ;
  - cache tronqué, panne réseau pendant le téléchargement, session en cours ;
  - fusion du catalogue paginé ;
  - garde « aucune note calculée sur l'appareil ».

## Limites et points ouverts

- Les modules ne sont téléchargés que pour les programmes suivis (taille des données). Un programme non suivi s'affiche dans le catalogue ; ses modules nouveaux sont téléchargés au moment où l'élève le choisit (connexion nécessaire).
- Un module publié inaccessible (pas de droits, hors connexion au premier choix) apparaît comme non publié jusqu'au téléchargement.
- Test de positionnement et concours blanc hors connexion sur des exercices téléchargés : les réponses en attente comptent zéro dans le résultat local affiché comme provisoire. Le serveur recalcule la note du concours blanc à partir des tentatives ; la progression serveur remplace ensuite la copie locale.
- Le cache HTTP (ETag/304) n'est pas utilisé côté mobile : la comparaison révision + empreinte du manifeste évite déjà tout retéléchargement inutile. Le serveur garde ses contrôles d'accès avant 304 (lot 3).
- Pour activer la publication dynamique en local, l'import du lot 3 (`node scripts/migrations/lot3.js --uri=…fatafalta-dev --links=… --apply`) doit être fait avec des rapprochements d'organismes. La base `fatafalta-dev` reste en génération 0 tant que ce n'est pas fait, ce qui laisse l'app sur le pack embarqué.
- La reprise entre appareils (position de leçon, sessions, journal d'actions) relève du lot 5.
